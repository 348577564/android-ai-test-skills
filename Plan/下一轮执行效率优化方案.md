# 下一轮执行效率优化方案

## 1. 目标与范围

本轮优先解决“执行慢”，而不是扩建通用测试平台。

目标：在不降低预期覆盖、证据完整性和结果可信度的前提下，减少单条用例的端到端耗时，以及人类测试员的介入、复核时间。

核心方向：

> Agent 始终主控，持续理解任务并依据当前现场决定每一步；工具负责准确操作、采集和记录。每步都看结果，但不是每步都从头研究任务。

保留自然语言用例输入，不要求测试员先编写 YAML、Python 或 App 专属导航配置。经验指导操作，现场决定操作；陌生 App 和变化的界面也应能执行。

本计划基于代码静态检查，尚未进行设备性能实测。下面的耗时估计不是基准结果，验收阈值是建议目标。

### 当前实现范围

已实现本轮选择的第 0 步与计时基础设施：记录失败显式报告、finish 提交前校验与事务、
finding 多事件证据绑定、独立启动器与调用对账，以及 act/observe/read 的阶段计时。
调用结果与记录完整性分开报告；未执行的拒绝不生成记录损失标记。清单按会话组织，
正常返回不展开计时；补充会话墙钟、返回字节数、序列化、OCR 结果转换和崩溃取证阶段。
OCR 库内部处理与宿主推理等无法独立测量的部分仍明确为未知，不以日志窗口长度替代耗时。
回归使用临时存储和假设备；具体接口见 [环境与工具参数](../docs/环境与工具参数.md)。

这不代表所有计划完成。尚待专用设备按 3.2 采正式基线；宿主推理耗时、完整预期覆盖仍需
宿主记录与逐项审计。任务状态、find/元素操作、统一轮询、区域 OCR 和常驻服务属于后续工作，
按基线结果选取，不在本次实现中改变执行策略。

## 2. 当前瓶颈与依据

| 瓶颈 | 当前实现 | 判断 |
|---|---|---|
| 模型与工具往返 | 每次 act 返回后，由模型决定下一步 | 必须实测；逐步判断是必要能力，优化重复理解、冗余调用和返工，而非取消主控 |
| 固定等待 | act 默认 settle 600ms；权限检测首轮默认窗口 800ms | 无权限弹窗的普通动作通常承担约 1.4s 基础等待，另加通信、采集等开销 |
| 证据采集串行 | screenshot → dump_hierarchy → app_current 等操作 | 应拆分计时；不能凭感觉删截图或盲目并行 |
| OCR 重复初始化 | 每次 read 命令创建 RapidOCR 实例 | 当前 OCR duration 不含初始化，实际调用成本可能被低估 |

| 返回信息重复 | act 同时返回 next 和 nodes | 精简普通返回，实测对工具间隔、判断准确性和端到端耗时的净影响，不预设收益排序 |

## 3. 第 0 步与第一阶段：可信记录和端到端基线（P0）

### 3.0 先建立可审计的记录与结论管道

正式基线与验收依赖以下三项先完成：

- **记录失败显式化**：log_auto 检查事件写入结果，向调用方返回调用 ID、会话 ID、失败阶段和错误。动作已执行但记录失败时明确区分，不自动重放；证据链无法可靠继续时暂停处理。
- **finish 校验前移**：在提交结论、清除当前会话和回写用例统计之前校验。校验与数据库提交采用一致的事务边界；拒绝或提交失败时不污染统计，保留可处理的会话。
- **finding 绑定证据**：接入 event_id 并校验所属会话，支持需要多步骤证据的断言。不得默认以最近事件替代正确证据；未验证、阻塞项如实说明原因。证据关联提供可追溯性，仍需按原始预期逐项审计覆盖与判定。

对账基准优先取自**宿主侧完整工具调用记录**，包含唯一调用 ID、开始/结束或中断、退出状态，与数据库事件关联。若宿主无法提供这些字段，增加独立启动器在启动工具前后记录调用边界。数据库事件不能作为自身完整性的唯一证明。

独立清单也须验证写入与关联完整性。仅由工具进程自报时，明确无法覆盖进程未启动或自报前退出等情况；缺少可靠调用清单的样本不作为完整基线。宿主批量调用与内部子操作分别编号，避免一次外层调用掩盖内部漏记录。

用独立临时存储验证写失败、记录缺失、进程中断、跨会话证据、无效结论及事务失败。第 0 步通过前可采集外部诊断数据定位问题，但不将其作为正式基线或验收依据。修复和新增记录的开销计入修复后的基线。

### 3.1 计时范围

端到端耗时不能只用工具内部的 duration_ms。应同时记录：

| 指标 | 内容 |
|---|---|
| 用例墙钟时间 | 开始到完成，包括模型决策、工具调度、设备等待 |
| 工具间隔 | 上次工具结束到下次工具开始；包含模型、宿主调度、传输，不能直接等同于模型推理时间 |
| 启动与连接 | 进程启动、模块导入、设备连接 |
| 动作 | 点击、输入、滑动等设备调用 |
| 等待 | settle、目标条件等待、权限轮询 |
| 采集 | 截图获取、PNG 保存、dump、前台状态、元信息写入 |
| 崩溃检测 | 检测与异常发生后的取证分别计时 |
| OCR | 导入、初始化、图像处理、推理、结果转换 |
| 记录与返回 | 数据库写入、节点构建、序列化及返回大小 |

工具内部使用单调时钟测持续时间，墙钟时间用于跨调用关联。不同机器的墙钟不能未经校准直接相减。分阶段计时须避免重复累计。

计时数据进入已有事件或元信息，不默认增加大量模型可见输出。无法测到的阶段标为“未知”，不填零。

进程启动由外层调用记录计时，导入/连接由内部阶段计时，避免漏计启动前开销。OCR 初始化与首次推理分别记录；首次 ocr 调用内的开销已处于当前 duration 区间，不能重复计入“漏计 warmup”。

### 3.2 基准用例

选择三类真实流程：

1. UI 树完整、导航稳定的普通功能用例。
2. 首次启动或权限分支用例。
3. 包含 toast、Canvas 或 OCR 的用例。

固定设备、应用版本、模型配置、网络条件和前置数据。冷启动、热启动分开统计；记录权限和数据状态，不能用清数据代替升级前置。

每条选定的常规基准用例，基线与优化配置各计划至少 5 次运行。另选无知识卡或入口/文案变化的留出用例，不参与针对性调优，每条在两种配置下各计划至少 3 次运行。

记录全部尝试、有效完成数、失败/阻塞/记录不完整原因；有效完成的耗时报告中位数和范围，未完成运行另报耗时与停止原因，不静默排除。小样本仅用于试点判断，不声称稳定 P95 或总体完成率。人工等待时间单独统计，同时保留完整墙钟时间。

### 3.3 阶段交付与决策

- 一份端到端耗时分解和原始测量数据。
- 各类流程的模型调用数、工具调用数、截图数、OCR 次数、人工介入次数。
- 调用清单与事件的对账结果，以及重复观察、重复检索、重新规划、错误点击和返工的轨迹分类。
- 按总耗时贡献排序的瓶颈清单。

若工具间隔占主要耗时，优先第二阶段；若 OCR 或采集占主要耗时，优先相应专项。不要在基线之前同时改多条链路。

启动、模块导入、连接和 OCR 初始化是否属于头部贡献者作为待验证假设。若实测累计贡献靠前，且复用能带来可观净收益，则提前试点 5.3 常驻服务，同时验证隔离、故障处理和兼容性。

按实测占比估算收益：若某阶段占墙钟比例为 p，该阶段耗时减少比例为 r，则其他条件不变时端到端减少约 p×r；多个改进须避免重叠计入。30% 是试点目标，没有结构性保底。例如工具侧占 30%，其耗时减半只贡献约 15% 端到端改善。

若第二阶段后工具间隔仍占主导，且目标不可达，依次执行：

1. 拆分可测的宿主调度、传输与模型开销，未知部分明确标记。
2. 在宿主支持范围内试验会话复用、上下文组织、调用调度和独立工作并行，单独比较净收益。
3. 报告实际收益和剩余限制；需要调整目标时先确认并记录新目标、理由和后续工作，再验收，不事后把未达标改称达标。

同一设备上有状态依赖的动作与现场判断保持顺序；仅并行无相互依赖的工作，例如分析已有证据或查询不同知识小节。批处理只合并已知且互不依赖的查询，不跨过中间观察或检查点。

## 4. 第二阶段：连续任务上下文与现场短决策（P1）

### 4.1 理解一次，持续跟踪任务

Agent 开始时理解目标、前置、步骤与预期，之后持续维护：

- 当前目标和用例步骤。
- 已完成、待验证、阻塞的预期。
- 最近现场证据与不确定事项。
- 下一动作目的和已尝试次数。

不在每步重复读用例、整张知识卡或重新规划。Skill 无法独自控制宿主推理预算和压缩行为，须先核实宿主能力，不能声称精简提示词必然缩短推理时间。

紧凑状态作为一个会话内产物，同时用于 pause --ask 交接和上下文压缩后的恢复。按关键进度变化更新，尽量与已有调用合并；只在恢复或疑似上下文遗失时单次读取，不增加每步独立读写命令。恢复信息标注时间与证据引用，旧状态不等于最新画面。

### 4.2 每步看现场，明确时短决策，意外时深入判断

```text
Agent 读取上一动作返回
  → 确认实际结果与预想是否一致
  → 验证当前检查点
  → 下一目标明确：决定并调用下一动作
  → 目标不明确：查完整 dump / OCR / 看图 / 查相关经验
  → 无法收敛：带证据问人
```

普通步骤只保留必要判断和动作理由；异常步骤允许深入观察与思考。不批量盲点，不由工具自行规划导航。纯验证时允许 observe，不为减少调用而跳过检查。

### 4.3 经验作为提示，不作为脚本

知识卡用于解释入口、控件特征和已知交互，不规定必须照抄的路径。只读相关小节，本会话已有且仍适用的经验不重复检索。

经验与现场冲突时采用现场证据；历史 bug 不替代本次验证。没有知识卡也能执行，不要求先建图或维护导航配置。

### 4.4 工具承担机械工作，不承担测试决策

优先试点完整 dump 的 find 与按当前元素标识操作，减少翻查和手拼坐标。元素标识绑定观察，执行前校验目标；过期、歧义、不可用时显式返回，不默认选第一项。

校验自身耗时须计入净收益。自绘控件保留视觉和现场坐标方式，不声称元素接口解决所有场景。复用现有动作、证据和崩溃拦截能力，保留旧逐步动作接口兼容。

每步仍留证据；动作已执行但采集失败时不自动重放。工具不自行换入口、重启、清数据或判 PASS。主 Agent 遵守用例与终态约束，遇到不确定情况停下判断或问人。

## 5. 第三阶段：降低工具固定开销（P1）

### 5.1 统一动作后等待、权限检测与落点观察

将当前串联的 settle 与权限轮询合并为一个有界状态机，共享时间预算及同轮可用的前台状态、UI 信息，避免重复空等。Agent 提供目标条件和权限意图；工具只检查条件、按策略处理，不规划业务路径。

| 观察结果 | 处理 |
|---|---|
| 权限弹窗出现 | 按明确策略处理，或交回 Agent；处理后继续确认，不能作为成功早退条件 |
| 目标满足、必要稳定条件满足，且无待处理阻塞弹窗 | 正常返回并保留检查点证据 |
| 画面稳定但目标不满足 | 继续有界等待，不判到达目标 |
| 无明确目标 | 使用经过验证的有界观察策略，只返回现场，不宣称目标完成 |
| 超时、崩溃、断连、采集失败 | 返回具体未满足条件或异常，遵守终态约束，不自动重放 |

最短观察窗口、稳定窗口、轮询间隔与超时根据场景测量。短间隔不保证捕获所有延迟弹窗，应覆盖不同延迟、设备负载和 OEM 情况，说明支持范围。不要简单将 settle 设为零；静态 UI 树不保证业务已完成。

普通动作等待低于 0.8s 是可验证的实验目标，不是通用默认值或性能承诺；测量轮询新增通信成本，确认净收益。

由 Agent 根据用例和当前动作提前声明权限意图；未知流程保留检测兜底，不能仅凭入口名称断定不会弹框。测试延迟弹窗、多权限连续申请、拒绝分支及已授权状态，不把某台设备约 6 秒的现象当作 Android 通用保证。

纯观察应无点击副作用；需要组合处理时显式启用，并保留处理前后证据。这也有助于减少状态被自动改变后的返工。

### 5.2 OCR 真正按区域计算

- region 在推理前裁剪，而非仅在推理后过滤。
- 返回坐标加回裁剪偏移；归一化坐标仍以原图尺寸计算。
- 若使用缩放，先反算比例，再反算偏移。
- 校验越界、空区域和错误参数，不静默回退整图。
- 优先复用已有证据截图，避免重复现场截图。

对比整图与区域识别的文本召回、坐标误差和总耗时。裁剪会影响文字上下文，不能只看速度。

当前 region 是“识别后按中心点过滤”。改为裁剪可能改变边界文字识别结果，应通过显式模式先试点，验证后再决定默认行为，并更新参数说明。

### 5.3 有依据地引入常驻执行

仅当测量证明连接、导入或 OCR 初始化占比显著时，再引入本地常驻服务，复用设备连接和 OCR 模型。

服务必须具备健康检查、显式设备/会话绑定、断连错误、资源释放与重启行为。每台设备串行执行，不复用一个全局当前会话指针承载并发任务。

## 6. 第四阶段：减少返回与检索成本（P2）

- 普通导航返回 next、状态摘要、截断标记和证据引用。
- 验证步骤返回所需完整字段；原始 dump 始终可查询。
- 提供针对完整 dump 的 find，减少反复 observe 和人工翻查。
- 节点列表显式标记过滤范围、总量及是否截断。
- 已有观察仅在状态未变化且仍新鲜时复用，不能长期缓存坐标。
- 不按 observe/act 比值强制限制观察；纯验证和动态页面需要合理观测。

这些调整与短决策循环配套验证，不以减少主模型判断次数为强制目标。不要为了缩短返回牺牲判断所需的信息。

## 7. 验收目标与回退条件

建议在固定试点用例上采用以下目标：

| 指标 | 建议验收标准 |
|---|---|
| 冗余调用与返工 | 重复观察、读卡、重新规划及错误点击减少；必要判断和观察不计冗余 |
| 陌生/变化界面 | 无专属导航配置仍可执行，留出用例有效完成率不下降 |
| 试点用例端到端中位耗时 | 试点目标相比基线降低至少 30%；按 3.3 估算可达性，未达标如实报告 |
| 预期覆盖 | 与基线一致，不漏验证 |
| 证据完整性 | 每个必要动作、检查点可追溯；记录失败显式暴露 |
| 基线完整性 | 独立调用清单与事件可对账；缺段、中断、失败样本单独报告 |
| 异常返回 | 缺元素、歧义、错误落点、断连、采集失败、崩溃均不继续盲执行 |
| 人工成本 | 介入与复核时间不增加，单独报告 |
| 判断正确性 | 本次样本不得出现新增误判 PASS；不据此声称总体误判率为零 |

采用同一前置下的基线/优化配对比较，交替运行顺序，避免缓存、网络与数据变化影响结论。恢复测试数据的操作与时间单独记录。

若提速依赖少留证据、跳过预期、跨过检查点或增加人工返工，则不算验收通过。发现此类情况，回退到原有逐步执行入口，保留异常样本用于修正。回退仅针对性能策略，仍保留证据绑定与提交前校验，不恢复静默记录或无证据提交。

## 8. 回归测试

新增测试优先覆盖：

1. 完整 dump 查询、元素匹配歧义、过期观察、超时和错误落点。
2. 中途崩溃、断连、动作后采集失败时不重放。
3. 每步事件、证据和会话关联正确。
4. 权限延迟出现、多权限、拒绝策略。
5. OCR 裁剪/缩放后的原图坐标与边界行为。
6. 原有逐步动作接口保持兼容；finding 强制显式证据、finish 提交前硬校验为有意收紧的接口约束，迁移方式见工具文档。
7. 记录失败、调用缺失和进程中断可对账；finish 拒绝及事务失败不污染统计，证据关联校验同会话。
8. 统一轮询覆盖目标先出现、权限延迟出现、多权限切换、稳定但未到目标、超时及崩溃。
9. 暂停交接和压缩后恢复保留待验证项，旧状态、证据缺失与写失败显式暴露。

所有回归使用独立临时存储和假设备，不修改正在使用的 sessions.db、current_session 或崩溃标记。真机基准在专用测试会话内执行。

## 9. 推荐实施顺序

0. 按 3.0 完成可信记录、结论提交、证据关联和独立调用对账，验证失败路径。
1. 补齐计时，按 3.2 测常规与留出用例，按 3.3 排序瓶颈并估算目标可达性。
2. 试点紧凑任务状态、短决策循环及按需经验检索，保持同一 Agent 主控；按耗时贡献选择 find、按元素操作等通用改进。
3. 将统一等待/权限轮询作为一个工作项试点，区域 OCR 独立对比。
4. 按实测启动、连接及初始化贡献决定常驻服务优先级；工具间隔仍占主导时执行 3.3 的宿主侧评估与目标处理流程。
5. 完成异常回归与配对验收，推广有效的通用能力。

每项完成后更新直接相关的工具参数和 Skill 使用说明。最终交付应包含可运行实现、回归结果、基准对比、已知限制和回退入口。

**本轮成功标准不是“工具调用更少”，而是“更快交付一条人类能够采信的测试结果”。**
